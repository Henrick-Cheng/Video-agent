# AI 辅助开发工作流 —— 从 Video-agent 实践提炼

> 2026-07-14 整理。来源：本项目 15 个 Phase / 84 commits 的实际做法，
> 按 `project_review_202607.md` Q17（"如果重做会改什么"）的复盘修正——
> 项目里迟到的实践（如 CLAUDE.md 到 Phase 14.4 才立）在本工作流中放回
> 它们本该在的位置。每个环节都附本项目的真实案例作为依据。
>
> 核心洞察：**AI 生成代码的最大风险不是写错，而是"看起来合理、实则虚构"。**
> 错误的代码测试能抓；虚构的 mock 数据、模板残留、估算结论会安静地活到
> 污染结论为止。整套工作流的目的就是把"诚实性"从自觉变成可测试的契约。

---

## 阶段 0 — 立项：先定验收，再定框架

**在写第一行业务代码之前确定：**

1. **验收标准先行**：这个项目"做成了"由什么数字说话？评测协议
   （基准集、judge、指标口径、基线）在架构之前定下来。
   - *教训（Q17-②）*：本项目中途换过评测协议（EM → LLM-judge、自建集 →
     MMBench-Video），每换一次旧数据全部重跑。协议先行可避免。
2. **观测口径从第一天接真实数据**：成本 / 延迟 / 用量一律取自 API 返回的
   真实 usage，不用估算。
   - *教训（Q17-①）*：字符数估算 token 的语言偏差让"1/4 成本"的错误结论
     活了两个月，最后靠 `UsageLedger` 才暴露并撤回。
3. **技术选型 = 成本分配判断**：项目重心之外的部分用成熟封装，不自研。
   - *本项目*：编排用 LangChain `create_agent`（重心在记忆架构与评测，
     不在框架）；但要求能讲清封装底层（recursion_limit 推导、重试补丁）。
4. **骨架一次到位**：`src/`（按职责分包）、`tests/`、`docs/`、`configs/`
   （分层配置：YAML → .env → 环境变量）、CI 空跑通。

## 阶段 1 — 立约：CLAUDE.md 人机契约（第一天就写）

给 AI 的约束条款，每次会话自动生效。最小四条（本项目 `CLAUDE.md` 原文）：

1. **mock / fallback 必须显式标注**（`[MOCK]` 前缀 + `mock_*` 命名 +
   `source:"mock"`），且**永不虚构领域数据**——mock 可以驱动真实工具循环，
   但最终输出只能是无内容占位。
2. **真实路径失败必须 fail-loud**：后端不可用返回 `{"_mode":"error"}`，
   绝不静默降级编造证据。mock 仅显式开启（`--mock` 标志）。
3. **每条 CLI 模式 / 降级路径至少一个端到端行为测试**；
   "assert agent is not None" 不算测试。
4. **AI 生成的占位 / 示例内容必须人审后才能合并**；新行为先写（或共写）
   约束性测试——测试是人机之间的验收合同。

另加两条项目约定：语言（代码与模型可见输出用什么语言）、
当前架构主线是哪条（防 AI 在旧线上继续开发）。

- *为什么第一天写*：本项目这四条全是事故逼出来的（见阶段 2 的事故表），
  每条的代价是数小时到两个月不等的返工。

## 阶段 2 — 功能开发循环（人机分工的最小单元）

每个功能 / 修改走同一个环：

```
人:  定需求 + 写/共写约束性测试(该功能"对"的定义)
      ↓
AI:  实现(允许它同时补测试,但约束性测试的验收标准人来定)
      ↓
机器: 全量离线测试绿 + CI 绿
      ↓
人:  实跑主路径一遍(不是跑测试,是真的跑产品入口)
      ↓
人:  审 AI 输出中的三类高危物: 占位文字/示例数据/prompt 措辞
      ↓
commit(信息写"为什么",不只"做了什么")
```

**"测试绿 ≠ 完成"是这个环的关键**，因为 AI 辅助开发有三类测试抓不住的风险，
每类本项目都真实踩过：

| 风险类型 | 本项目事故 | 固化的对策 |
|---|---|---|
| **虚构数据** | 早期 mock 伪造带时间戳的场景图三元组，混进评测即假证据 | 诚实 mock 契约 + guard 测试 `test_mock_answer_is_labeled_and_fabrication_free` |
| **模板残留** | 报告生成器每次写入 `_TODO: Replace placeholder results..._`，与真实数据自相矛盾共存 | 占位内容人审规则；发现即删源码模板 |
| **路径盲区** | wordnet 懒加载 bug：mock 路径短路绕过、53 个测试全绿，真实路径首步就崩 | **收尾务必实跑主路径**；此前 10 个"环境性失败"实为同一 bug |

## 阶段 3 — 架构迭代：评测驱动，旧版不删

架构级判断（重构、换方案）不靠直觉拍板，走这个循环：

1. **预测留档**：动手前把预期写进日志（"我认为 X 会赢因为 Y"）。
   - *本项目*："睡前预测长视频是 agent 舒适区——半对半错，第四次被实测
     纠偏，教训仍是实测优先"（progress.md 原文）。预测留档让"被纠偏"
     可见，防止事后合理化。
2. **迭代即基线**：旧版本不删，留作评测对照组（v0=`rag_only`、
   v1=`agent`、v2=`agent_v2` 三代同场）。重构有效性由数据证明，
   不由口头声称。
3. **评测卫生**：基线输入与被测系统完全解耦。
   - *事故*：为 Agent 调的 `keyframe_count` 悄悄改写了基线的输入帧，
     跨 Phase 对比全部失效，"关系推理 2.7×"结论作废。
4. **统计纪律**：主结果 runs=N 带 ±std；gap 与噪声带比较后才下结论。
5. **负结果留档**：证伪的方向（routing oracle、caption 加密）完整记录
   为"已评估、已放弃"——防止后续会话（人或 AI）重新提议死方向，
   也是"该换数据集而非继续榨残差"这类战略判断的依据。

## 阶段 4 — 阶段收尾：日志与文档同步

每个 Phase（约 1-2 周或一个主题）结束时：

1. **progress.md 编年**：做了什么 / 结果数字 / 踩的坑（原因+解决）/
   **判断失误复盘** / 下一步。这是 AI 可读的项目史——新会话冷启动时
   AI 靠它接上上下文。
2. **文档如实同步**：未验证的东西如实标注（本项目 README 对 vLLM 后端
   写"接口预留、无 GPU 未实跑"，不过度宣称）；过时文档归档到
   `docs/archive/` 而非堆积（见 `docs/README.md` 索引）。
3. **结论变更要追溯**：撤回的结论（"1/4 token"）在所有引用处更新，
   并留下撤回原因——主动撤回失实卖点本身是可信度资产。

## 阶段 5 — 跨会话上下文管理

AI 会话是无状态的，项目不是。三层上下文让新会话立即接上：

| 层 | 载体 | 内容 |
|---|---|---|
| 硬约束 | `CLAUDE.md` | 契约条款 + 当前架构主线（随架构演进更新，如 v2 上线后标明"v1 = 基线 + mock"） |
| 项目史 | `docs/progress.md` | 编年日志；"为什么不做 X"的答案都在这里 |
| 权威数据 | 单一取数源文档 | 所有对外引用数字只从一处取（本项目 = `project_review_202607.md` §1.4），防止 AI 从过时文档抄旧数字 |

## 贯穿全程的分工原则

- **人负责**：方向与验收标准、约束性测试的"对"的定义、架构判断的
  最终拍板、占位/prompt/示例内容的审查、实跑主路径。
- **AI 负责**：实现、跑评测、整理文档、提出方案与自查。
- **机器负责**（不靠自觉）：契约条款 → guard 测试；回归 → CI；
  成本 → 真实计费账本。**凡是能写成测试的规范，都不要停留在文档里。**

## 一页速查（新项目启动清单）

```
□ 评测协议先行: 基准/judge/指标/基线,写架构之前定
□ 真实观测第一天接入(usage/成本/延迟,不用估算)
□ CLAUDE.md 人机契约: mock标注/fail-loud/行为测试/占位人审 + 架构主线
□ 骨架: src/ tests/ docs/ configs/ + 分层配置 + CI 空跑通
每个功能:
□ 人定约束性测试 → AI 实现 → 测试绿 → 实跑主路径 → 审占位/示例/prompt
每次架构迭代:
□ 预测留档 → 旧版留作基线 → 基线输入解耦 → runs=N±std → 负结果留档
每个阶段:
□ progress.md 编年(含判断失误复盘) → 文档如实同步 → 撤回结论要追溯
```
