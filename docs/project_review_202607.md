## 一、项目现状审核

### 1.1 一句话画像

把视频组织成三层 Lazy 记忆（L0 全局摘要+ASR / L1 按需段落 caption / L2 带溯源的三元组索引），Agent 走置信度驱动循环按需探索。MMBench-Video 150 题 runs=3 上 **1.984±0.101 反超公平基线 1.727±0.020**，抗噪成立、归因干净、每题只看 3.1 帧。

### 1.2 工程质量强项（面试可直接引用的证据）

| 强项 | 证据 | 为什么值钱 |
|------|------|-----------|

### 1.3 弱项（按对目标的伤害排序）

1. **无服务化形态**（伤求职-应用岗）：只有 CLI 和一个停在 Phase 6 的 v1 Gradio。没有 FastAPI/异步/并发/部署故事。
2. **单一子集、单一 judge**（伤论文）：主结果在自采样的 150 题子集上，与公开榜不可比；judge 是 qwen-max（自偏好风险，重评脚本已就绪待 key）。
3. **无横向方法对比**（伤论文）：只有自设基线（vlm_direct / vlm_transcript / v1），没有与 VideoAgent 等已发表方法在同一协议下对比。
4. **检索纯关键词**（伤技术深度提问）：`retriever.py` 是词形还原+关键词匹配，FAISS/embedding 在 requirements 里但未接。面试被问"为什么不用向量检索"需要准备好答案（见 §4.2 Q13）。
5. **Gradio 前端停滞**：仍接 v1、中文硬编码。要么接 v2 要么在 README 降权（本次已在 README 如实标注）。
6. **prompt 内嵌在 `react_agent.py`**（100+ 行 × 3 版本）：无版本管理，A/B 困难。小重构即可解决。
7. **vLLM 后端未实跑**（无 GPU）：README 已诚实标注，面试可讲"接口预留 + 为什么没验证"。

### 1.4 结果数据备忘（面试/论文引用统一从这里取）

- **MMBench-Video 150q runs=3**：agent_v2 **1.984±0.101** > vlm_transcript@8 1.727±0.020 > vlm_direct@8 1.478±0.025（0–3 制）；v1 1.193。
- **抗噪**：gap 0.257 > std 之和 0.121。**归因**：ASR 模态 +0.249，架构 +0.257。
- **时长桶**：<90s 基本持平（1.81 vs 1.76）；90–180s **2.10 vs 1.55**；>180s **2.05 vs 1.87** → 舒适区边界 ≈90s，越长越赢。
- **幻觉（HL）**：2.422±0.191，同模态基线 2.3×、直接看帧基线 3.9×——最硬的机制性卖点。
- **帧效率**：3.1 帧/题 vs 固定 8 帧（−61%）；150 题中 81 题免费检索直答、69 题自主升级探索。
- **成本**：agent 总 token ≈ 基线 2.1×（卖点是帧效率+长视频准确率，**不是省钱**——别在简历上写省成本）。
- **弱项维度**：TR 1.544 < 基线 1.767（时序增益主要来自 ASR 模态而非架构）——面试被问"哪里不行"时的诚实答案。
- **标注审计**：n=30，97% gold 被证据支撑 → 离满分的差距是模型能力不是烂标注。
- **AGQA 70q runs=1**：overall 0.436（judge 口径）；duration **0.682**（强项）；open 0.190 / sequencing 0.286（弱项，开放词表 + 时序仍难）。

## 二、论文发表潜力评估

### 2.1 贡献点提炼（论文的三条主张）

1. **场景图的角色重定位**：从"有损的答案压缩"（v1，纯三元组 RAG 只保住直接看帧约一半信号）→ "多模态证据的时序索引"（三元组挂 seg 溯源，命中即回带完整 caption + 旁白）。v1→v2 的失败-诊断-返修本身就是论文最有说服力的 motivation。
2. **Lazy 按需建图 + 置信度驱动感知预算**：建图从预处理变成逐题 Agent 决策；81/150 题零探索直答、3.1 帧打赢 8 帧，感知预算按需分配可量化。
3. **归因方法论**：`vlm_transcript` 公平基线把"多模态"与"架构"两个变量拆开（+0.249 / +0.257），排除"赢只靠加了 ASR"——这是很多同类论文没做干净的事，审稿人会认。

### 2.2 与前沿的定位与撞车风险

这个方向（LLM agent 做长视频理解）2024–2025 已相当拥挤，投稿必须写清差异：

| 相关工作 | 它做什么 | 本项目的差异点 |
|---|---|---|
| **VideoAgent**（ECCV'24, Wang et al.） | LLM 迭代选帧，EgoSchema 上 8.4 帧/题 | 它只有帧选择，无结构化记忆；本项目有可溯源的三层记忆 + 三元组索引 |
| **VideoAgent**（memory-augmented, Fan et al.'24） | 时序+物体两个记忆库，预处理阶段全量构建 | **预建 vs Lazy 按需建**是关键差异——本项目把建图变成逐题决策并量化了收益 |
| **DoraemonGPT**（ICML'24） | 符号记忆（表格）+ MCTS planner | 记忆是表格非图；无置信度驱动的预算控制 |
| **Deep Video Discovery**（MSR'25） | 多粒度片段库 + agentic search | 思路最接近（多粒度+按需）；差异在三元组证据索引 + 归因评测方法论 |
| **VideoTree / LLoVi 等** | 层次化 caption / 全片转写进 LLM | 静态 pipeline，无 agent 决策 |

**撞车风险评估**：架构层面"lazy + 多粒度 + 置信度"各元素都有先例，**纯架构新颖性不足以支撑 CCF-A/B 主会**。可辩护的组合创新是：①按需建图作为逐题决策（含负结果证明何时不该探索）；②图=证据索引而非答案来源的明确立场与消融；③模态/架构归因协议。写作时建议把 **evaluation methodology 拉高为共同贡献**，而不是只卖架构。

### 2.3 按投稿层级的差距清单

架构完整、主结果 runs=3 抗噪、消融干净、负结果与局限诚实、演进过程 1137 行留档。答辩叙事建议直接用 v1 失败→诊断→v2 反超的弧线。风险仅剩答辩委员问"为什么 judge 是 qwen"，届时最好已完成 gpt-4 重评。

## 四、面试准备包

### 4.1 项目讲述（三个版本）

**30 秒（电梯稿 / 自我介绍带一句）**
> 我做了一个视频问答 Agent：把视频组织成三层懒加载记忆——全局摘要、按需段落描述、带时间戳的三元组索引——Agent 先免费检索，自评置信度，不够才自己挑一段视频细看。在 MMBench-Video 上比直接看帧的 VLM 基线高 34%，每题只看 3.1 帧对方看 8 帧，幻觉指标是基线的 2.3 倍好。

**2 分钟（项目介绍环节）** — 按"两次迭代：失败→诊断→重构→验证"弧线讲：
1. *起点（两次迭代的第一次）*：项目最初是「感知-构图-检索-回答」**固定 pipeline**（v0）——每题走相同步骤、同样粒度，无差别全量处理；第一次迭代改造成 ReAct Agent（v1），调用顺序与粒度变成模型按意图的运行时决策，但保留了"全片预建场景图"的惯性。真实计费口径复测发现 v1 仍**输给直接看帧的基线**（1.19 vs 1.48）。
2. *诊断*：两个设计错误——三元组是有损压缩，VLM 看到的属性/文字/因果在"只输出 JSON 三元组"这步丢光；全量预建在每视频约 1 题的场景下成本永远摊不回。
3. *重构*：对照 VideoAgent、DoraemonGPT 等前沿收敛的共识，重写为 v2——图降级为"证据的时序索引"（三元组挂溯源，命中回带完整 caption+旁白），建图变成逐题的 Agent 决策，置信度驱动是否探索。
4. *验证*：runs=3 抗噪反超（1.98 vs 1.73，gap 大于两倍 std 之和）；用同模态公平基线把增益拆成 ASR +0.25 和架构 +0.26，排除"赢只是因为多了个模态"；另外做了两个负结果实验证明剩余差距是 VLM 能力天花板而不是编排问题。
5. *收尾*：整个过程沉淀了一套 AI 辅助开发的工程规范——fail-loud、可审计 mock、53 个离线测试 + CI。

**5 分钟版**：在 2 分钟版基础上展开三处——①三层记忆的读写路径（search_memory 三层联合检索 → 命中三元组回带 caption；explore_segment 写 L1+L2）；②置信度循环的预算控制（每轮 ≤2 次探索、≤3 轮、"图里没有"不许当"否"）；③评测工程（VLMEvalKit 协议复刻、真实 usage 账本、judge 偏差披露与 gpt-4 重评预案、标注审计 97%）。

### 4.2 深挖问答（20 题，按被问概率排序；Q0 为必问核心题）

**Q0（必问）这个项目的真实优势到底是什么？**
统一口径：**长视频上的多模态证据定位与整合**——不是"推理更强"。

*这个口径的白话解释（面试官反问"这话什么意思"时用）*：长视频问答的答案几乎从不依赖整段视频，只依赖散落在时间轴上的几秒画面和几句旁白（=证据）。短视频均匀抽 8 帧什么都盖得住；视频一长，均匀采样大概率漏掉关键瞬间——所以长视频的瓶颈不是"看懂一帧"（VLM 本来就会），而是"在有限帧预算内**找到**该看的那几秒和该听的那几句（定位·多模态），再把它们**放到同一条时间轴上**组合成有据可依的答案（整合）"。最终推理的 LLM 与基线是同一个——赢在送进上下文的证据质量，不是赢在脑子。系统组件一一对应：L2 时间戳索引 + explore_segment 自选时间窗 = 定位；ASR 转写全量入 L0 = 音频模态廉价索引；三元组命中回带 caption + 旁白 = 整合；「缺席≠否定」= 整合纪律（幻觉 2.3× 是其可测结果）。

*为什么敢加"长视频"限定（也是被问"短视频怎么办"的答案）*：<90s 桶 agent 与盲采基线打平（1.81 vs 1.76）且成本更高——短视频的正确工程选择就是直接调 VLM，我的数据自己就是这么说的。限定词不是收缩而是主张可守的原因。同时适用范围与优势区间是两回事：lazy 设计让短视频/简单题自动走零探索轻量路径（免费检索直答），全时长可用、精度不吃亏——但那不是这套架构存在的理由。三个兑现点：① >90s 优势单调增长（有指导采帧 vs 均匀盲采：90–180s 2.10 vs 1.55、>180s 2.05 vs 1.87）；② 幻觉抵抗 2.3×（证据接地约束的机制性收益）；③ 细粒度感知维度全胜（FP-C 2×、FP-S、CP——按需 zoom-in 的收益）。主动补刀一句："推理类维度（TR/RR/AR）与基线基本打平，因为推理共用同一个 LLM——**这个架构买的是看得准，不是想得深**。"两层主张进可攻退可守：系统级 +34%（含 ASR 模态，长视频理解本就该用上旁白）；被质疑"是不是就靠加了 ASR"时，掏出架构级独立贡献 +0.257（同模态公平对照）。措辞纪律：「时序结构化索引」（机制，duration 5×/FP-C 2× 兑现）可以讲；「时序推理更强」（mmbv TR 是输的维度）不主动宣称。

**Q1 为什么用场景图？现在还需要它吗？**
要点：诚实承认 v1 把它当答案来源是错的；v2 里它的价值是**带时间戳的可检索索引 + 证据溯源**——三元组命中能定位到"哪一段、哪几帧、当时的完整描述"，这是纯 caption 列表做不到的结构化定位能力。同时给数据：纯三元组 RAG 只保住直接看帧约一半信号，所以证据本体必须是 caption+旁白。

**Q2 v1 为什么失败？你怎么发现的？**
要点：不是"感觉不好"，是真实计费口径复测发现 1.19 < 1.48。两个机制原因（有损压缩 + 预建摊销不回）。加分点：主动撤回了旧的"省 token"卖点，因为发现估算方法有语言偏差。

**Q3 三层记忆为什么是三层？两层行不行？**
要点：三层对应三种成本/粒度——L0 一次性廉价全局（摘要+ASR），L1 按需昂贵局部（密集 caption），L2 是横跨两者的检索索引。去掉 L2 = 检索退化为线性扫 caption，丢时间戳定位；去掉 L1 = 回到 v1 的有损三元组。层数是由"检索要能溯源到证据"这个需求反推的。

**Q4 置信度是模型自评的，可靠吗？**
诚实答：**不完全可靠，这是已知局限**——Phase 14.1 发现 22/30 零探索题答对，说明整体偏乐观但侥幸成分存在；AGQA TR 上可见"图里有相关但不充分证据就直接答"的过度自信。缓解手段是硬预算上限 + "缺证据不许答否"的规则。改进方向：把判据从"有没有相关证据"细化为"证据能否支撑该题型所需推理"。（这题答得诚实反而加分。）

**Q5 怎么证明不是"多了 ASR 才赢"？**
要点：vlm_transcript 公平基线 = 同帧数 + 同旁白文字，只差架构。1.478 → 1.727（模态 +0.249）→ 1.984（架构 +0.257）。两个变量被显式拆开。

**Q6 judge 是 qwen-max 评 qwen 的答案，自偏好怎么办？**
要点：①承认风险且写进 README；②三个方法同 judge，偏好影响的是绝对分不是相对序；③gpt-4-turbo 重评脚本就绪、答案已缓存零推理成本，待 key 即跑；④标注审计 n=30 独立验证了 gold 质量。

**Q7 每题 3.1 帧凭什么赢 8 帧？**
要点：不是帧少本身赢，是**帧的选择有指导**——81 题 L0+检索就够（0 额外帧），69 题 Agent 根据问题自选时间窗看 ≤6 帧。基线的 8 帧是均匀盲采，长视频里关键瞬间大概率不在采样点上。时长桶数据支撑：<90s 持平（盲采够用），>90s 拉开（盲采漏事件）。

**Q8 幻觉指标 2.3× 是什么机制？**
要点：架构属性而非 prompt 技巧——答案必须 grounding 到检索命中或探索证据，"图里没有"必须先探索验证才能答否。HL 维度考的就是"视频里没有的东西你会不会顺着问题编"，证据链要求直接抑制了这类编造。

**Q9 最难的 bug / 工程坑？**（备 3 个，按对方背景选）
- *评测污染类*：早期 mock 会编造带时间戳的三元组，一旦混进评测就是假证据——由此定下 fail-loud + 可审计 mock 的契约，并写 guard 测试锁死。
- *模型行为类*：qwen 会输出带重复键/未闭合括号的 JSON（三级容错解析），还会把工具调用写成纯文本（pseudo-call 检测 + 纠正重问）。
- *统计类*：token 估算的语言偏差——中英文 char/token 比不同，导致旧"1/4 成本"结论虚高，改真实 usage 账本后撤回。

**Q10 负结果实验为什么留着？说明什么？**
要点：routing oracle（"知道何时不该探索"的上帝视角）反而降分 → 探索机制本身没问题；caption 加密不涨分 → 残差是 VLM 能力天花板不是搜索深度。两个负结果把"还能从哪挤性能"的问题关死了，才敢下"该换数据集复现而不是继续榨本集"的结论。

**Q11 成本是基线 2.1 倍，怎么向业务交代？**
要点：先纠正卖点——这个架构买的是**长视频准确率和幻觉抑制**，不是省钱。适用场景判断：90 秒内短视频用直接看帧就够（数据支持：<90s 持平）；长视频/高幻觉代价场景才值 2 倍成本。另外 token 成本里帧 token 只占一部分，3.1 vs 8 帧在视觉 token 贵的模型上会收窄成本差。

**Q12 视频变成 1 小时会怎样？**
要点：诚实说没测过（README 已标注），已知舒适区 ≈90s 起赢、最长测到 ~600s。可预期的失效点：L0 摘要 8 帧在小时级下太稀、探索窗口的盲选空间变大。曾评估过 locate_visual（先定位再探索），因收益/成本不划算明确 DROPPED——这个"评估过并主动放弃"的决策过程本身值得讲。

**Q13 为什么检索不用 embedding/FAISS？**
要点：工程优先级判断——先用词形还原+关键词跑通闭环并测出瓶颈；实测瓶颈在 VLM 能力和长视频定位，不在检索召回（负结果实验佐证）。FAISS 在依赖里、接口留好，是 P1。（如果面试官追问，承认长尾同义词确实会漏，属于已知局限第 5 条。）

**Q14 为什么用 LangGraph 的 create_react_agent 而不自己写循环？**
要点：项目重心在记忆架构与评测，编排用成熟封装是正确的成本分配；但要证明理解底层——能讲清 recursion_limit 怎么按预算推导（`main.py::_get_recursion_limit`：v2 循环 = iters×5+10）、pseudo-call 重试怎么在封装外补、工具怎么用闭包绑 session。如果岗位强调框架深度，可以说"接 FastAPI 时计划换成手写 LangGraph StateGraph 以支持流式中间态"。

**Q15 多轮对话怎么复用记忆？**
要点：VideoSession 跨轮持久，explored windows 和 L1/L2 累积；每轮重算 L0 context 前缀反映新探索。第二轮问相邻问题时常零探索直答——这是 agent 相对单次 VLM 调用的独有优势（也是论文亮点实验 S1 的方向）。

**Q16 mock 为什么要设计得这么严格？**
要点：AI 辅助开发的教训——生成的 mock 特别容易"看起来很真"，一旦静默 fallback，假证据会污染答案和评测分数且极难发现。契约：mock 必须视觉可辨（[MOCK] 前缀）、数据必须假得明显（mock_* 命名）、真实路径失败必须 fail-loud。这套规范写在 CLAUDE.md，被测试强制执行。

**Q17 如果重做会改什么？**
参考答案：①一开始就用真实计费口径，v1 的错误结论会早两个月暴露；②评测协议先行（先定 judge 和基线再写架构），避免中途换协议重跑；③prompt 从第一天就独立成模块带版本。

**Q18（应用岗）这个系统怎么变成生产服务？**
要点：①L0 预建异步化（上传即预处理，问答时 L0 已就绪）；②session 状态外置（scene graph 可序列化 → Redis/SQLite），支持横向扩容；③流式返回中间 trace（LangGraph astream 已支持）；④UsageLedger 天然就是计费/监控埋点；⑤限流与降级已有雏形（ASR 缺失→纯视觉）。可以顺势提 T1 的 FastAPI 计划（若已做完则直接 demo）。

**Q19 从固定 pipeline 到 Agent 的第一次迭代解决了什么？**
要点：v0 是「感知-构图-检索-回答」固定流水线——每题走完全相同的步骤与粒度，简单题浪费、难题不够用。Agent 化（v1）把"调什么工具、看多细"变成模型按意图的运行时决策，并引入 inspect_frame 按需精读。但第一次迭代只解决了**编排固定**，没解决**记忆有损 + 预建摊不回**——那是第二次迭代（v2）的事。加分点：两代前身都保留为评测基线（v0=`rag_only`、v1=`agent`），三代同场对照，重构有效性由数据证明而非口头声称。

### 4.3 简历 bullet 建议（可直接粘贴，按岗位取舍）

- 设计并实现视频问答 Agent（LangGraph）：三层 Lazy 记忆（全局摘要+ASR / 按需段落 caption / 可溯源三元组索引）+ 置信度驱动探索，在 MMBench-Video 150 题子集（runs=3）上以 **1.98 vs 1.48**（0–3 制，+34%）反超直接看帧 VLM 基线，每题仅访问 **3.1 帧 vs 基线 8 帧**（视觉预算 −61%）
- 建立**模态/架构归因评测**：设计同模态公平基线将增益拆解为 ASR +0.249 与架构 +0.257，runs=3 验证反超越过噪声带（gap 0.257 > 双方 std 之和 0.121）；幻觉维度达同模态基线 **2.3×**
- 复刻 VLMEvalKit 官方评测协议，实现线程安全**真实 API 计费账本**；据此发现并修正 token 估算的语言偏差，主动撤回失实结论
- 制定 AI 辅助开发工程规范：fail-loud 错误契约、可审计 mock、**53 个离线测试 + GitHub Actions CI**；负结果实验留档（routing / 取证深度证伪）
- （做完 T1 后加）将 Agent 服务化为 FastAPI 流式接口并容器化，L0 预处理异步化、session 记忆跨轮复用

> 注意：**不要写"节省 token/成本"**——真实口径下 agent 总成本是基线 2.1×，写了会被有准备的面试官抓住。帧效率（3.1 vs 8）是准确的说法。

### 4.4 面试叙事总原则

1. **主线是两次评测驱动的迭代：固定 pipeline（v0）→ ReAct Agent（v1）→ Lazy 记忆 Agent（v2）**，且旧版本不删——v0 留作 `rag_only` 基线、v1 留作 `agent` 基线，重构有效性由三代同场对照证明。有真实失败和数据驱动的返修，比"我做了个 agent 拿了高分"可信十倍。
2. **每个主张带数字，每个数字能溯源**（本报告 §1.4 是唯一取数源）。
3. **主动暴露一个局限再给缓解方案**（置信度过度自信 / judge 偏好 / 2.1× 成本），比被挖出来体面。
4. 被问不会的：区分"没做但评估过"（locate_visual、FAISS——讲决策过程）和"没考虑过"（诚实承认，现场给思路）。
5. **优势口径全场统一为「长视频多模态证据定位与整合」**（Q0）：系统级 +34% 与架构级 +0.257 分层使用；不主动宣称"时序推理更强"，时序牌只打「时序结构化索引」这个机制层措辞。

| "计数类问题上稳定取得 33% 的准确率优势" | v1 时期旧数据，当前评测口径下不存在此数字 | 换整体 +34% 反超 + 幻觉维度 2.3× + 归因拆解 |

### A.2 整段替换稿（可直接粘贴）

**技术栈**：Python · LangChain / LangGraph · Prompt Engineering · Scene Graph · faster-whisper (ASR) · DashScope / vLLM · LLM-as-Judge · MMBench-Video · pytest / GitHub Actions

**项目背景**：针对通用视觉大模型直推长视频时的理解瓶颈——均匀稀疏采帧难以定位分散在时间轴上的关键证据、旁白等跨模态信息无法利用、无差别全量处理导致算力浪费与信息丢失——历经两次评测驱动的架构迭代：「感知-构图-检索-回答」固定 pipeline → 基于 ReAct 的全量建图 Agent → 置信度驱动的「三层 Lazy 记忆」Agent，在公开长视频基准 MMBench-Video 上整体反超 VLM 直推基线 34%，且优势随视频时长单调增强。

- **设计三层 Lazy 记忆系统**：L0 全局层（稀疏帧摘要 + faster-whisper 本地旁白转写）、L1 段落层（按需构建的密集 caption）、L2 时序三元组索引（⟨主体, 关系, 客体, t_start, t_end⟩ 带片段溯源）；场景图从"答案来源"重定位为"多模态证据的时序索引"，检索命中三元组自动回带原始 caption 与旁白，消除结构化压缩的信息损失。
- **实现置信度驱动编排**：基于 LangGraph 构建 Agent，先零成本检索记忆作答并自评置信度，不足才自选时间窗按需建图（每轮 ≤2 次、最多 3 轮）；建图从预处理变为逐题决策，150 题中 81 题免探索直答、69 题自主升级探索，每题仅访问 3.1 帧（基线固定 8 帧，视觉预算 −61%）。
- **构建增量精化的外置记忆**：记忆存于 session 而非对话 messages，prompt 长度恒定；记忆随探索增量生长而不膨胀——实体命名一致性经三道防线保障（生成端 prompt 强制沿用已有命名 / 批内去重 / 跨批与既有图谱语义对齐），时序相邻三元组按时间窗合并防索引膨胀，inspect_frame 像素级新发现回写三元组索引；多轮问答复用已探索窗口，相邻问题可零探索直答。
- **搭建可复现评测体系**：复刻 VLMEvalKit 官方 0–3 评分协议，在 MMBench-Video 150 题分层子集 × 3 次重复实验中以 1.98±0.10 反超 VLM 直推基线 1.48±0.03，幻觉抵抗维度达同模态基线 2.3×；设计同模态公平基线将增益归因拆解为 ASR 模态 +0.25 与 Agent 架构 +0.26，排除"仅靠增加模态取胜"。
- **制定 AI 辅助开发工程规范**：针对 AI 生成代码"看似合理、实则虚构"的风险制定工程契约并以测试强制执行——Mock 输出强制显式标注且禁止虚构领域数据，真实路径失败必须 fail-loud 而非静默降级编造证据，每个 CLI 模式与降级路径配备端到端行为测试；规范沉淀为项目级 CLAUDE.md 人机协作契约，53 个离线测试 + GitHub Actions CI 持续守护。
- **落实工程可靠性**：线程安全 UsageLedger 记录全部 API 真实 usage，据此发现并修正早期 token 估算的语言偏差；DashScope / vLLM 双后端一键切换，ASR 缺失优雅降级纯视觉。
